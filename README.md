# Архивы: Ранние академические исследования гипервизоров (проект Disco из Стэнфорда, конец 1990-х) и забытый патент технологии KSM (Kernel Samepage Merging) до того, как облака стали дешевыми.

## Проблема компаний
Современные компании тратят огромные бюджеты на инфраструктуру (AWS, Azure или локальные серверы). Когда компания запускает сотни изолированных процессов, микросервисов (в Docker-контейнерах) или виртуальных машин для разработчиков, каждый из этих процессов отъедает гигантский кусок дорогой оперативной памяти (RAM). При этом 60–70% данных в этой памяти абсолютно идентичны: это одинаковые библиотеки ядра, системные модули Linux или дублирующиеся куски кода Node.js/Python. Компании буквально платят миллиарды за хранение терабайтов одинаковых нулей и единиц в RAM.

## Забытое решение
В конце 1990-х инженеры создали концепцию Memory Page Sharing. Специальный легковесный демон сканирует оперативную память в фоновом режиме, находит страницы с абсолютно одинаковым содержимым, схлопывает их в одну физическую страницу, а для всех остальных процессов оставляет лишь «ссылки» (работает принцип Copy-on-Write). Когда RAM была дорогой, это позволяло запускать в три раза больше виртуальных машин на одном физическом сервере. Индустрия забросила развитие этой идеи в гражданском софте, так как производители железа начали штамповать дешевую память, а облачным провайдерам стало выгодно продавать вам больше серверов, а не оптимизировать старые.

## MemoryGuard — Агент оптимизации оперативной памяти

Наш сервис автоматически управляет дедупликацией ОЗУ на Linux-хостах (KSM) через динамический ptrace-инжектор и предоставляет интерактивный веб-дашборд.

### Быстрый запуск через Docker

Мы используем легковесную сборку на базе GraalVM Native Image (~35 MB). Для сборки и запуска выполните следующие команды:

#### 1. Локальная сборка образа
Перейдите в каталог `memoryguard/` и запустите сборку:
```bash
docker build -t memoryguard:latest .
```

#### 2. Запуск контейнера
Контейнеру требуются привилегированные права, доступ к пространству PID хоста (`--pid=host`) и разрешения на трассировку процессов (`SYS_PTRACE`) для работы авто-инжектора:
```bash
docker run -d \
  --name memoryguard \
  --privileged \
  --pid=host \
  --cap-add=SYS_PTRACE \
  --security-opt seccomp=unconfined \
  -v /sys:/sys \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -p 8787:8787 \
  memoryguard:latest
```

После запуска дашборд будет доступен по адресу **`http://localhost:8787`**.

## Публикация в приватный Docker Hub

Если вы хотите загрузить образ в свой приватный репозиторий на Docker Hub:

1. **Создайте приватный репозиторий** `memoryguard` на сайте [hub.docker.com](https://hub.docker.com/).
2. **Войдите в аккаунт** через консоль:
   ```bash
   docker login
   ```
3. **Присвойте тэг образу** (замените `yourusername` на ваш логин Docker Hub):
   ```bash
   docker tag memoryguard:latest yourusername/memoryguard:latest
   ```
4. **Загрузите образ**:
   ```bash
   docker push yourusername/memoryguard:latest
   ```
   *Теперь скачать этот образ сможете только вы после ввода учетных данных.*
